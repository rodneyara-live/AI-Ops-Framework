# WF-vault-write-github: Writing to the Vault via GitHub PR

**Executed by:** Any agent with vault write authority
**Purpose:** Propose changes to the vault through a Pull Request on GitHub. **Free** zones are auto-merged without human intervention; **Gated** zones require Chief of Staff review.

> This workflow is the standard writing mechanism for all Atlas agents. No agent writes directly to the vault, always via PR.

---

## Prerequisites

| Requirement | Where |
|---|---|
| `GITHUB_TOKEN` with `repo` permissions | `/srv/finco/secrets/default.env` |
| `curl` and `python3` available in the container | Standard in the Atlas image |
| `vault-propose.sh` script | `_Vault/Atlas/agent/tools/vault-propose.sh` |
| `vault-merge.sh` script | `_Vault/Atlas/agent/tools/vault-merge.sh` |
| File content approved internally | Generated by the agent in the previous step |

---

## Steps

### Step 1: Prepare the content

The agent generates the file content in memory (does not write to disk yet). Before continuing, verify:

- The content passes all agent quality checks (sanitization, format, mandatory fields)
- The destination path is correct according to vault rules
- The vault zone type:

| Zone | Paths | Behavior |
|---|---|---|
| **Free** | `Meetings/`, `Dev/Backlog/`, `Operations/Cadences/`, `Products/*/Bitacora.md` | Immediate auto-merge after creating the PR |
| **Gated** | Everything else | Notify Chief of Staff and wait for manual merge |

---

### Step 2: Invoke vault-propose.sh

```bash
# Save the content in a temporary file
CONTENT_FILE=$(mktemp /tmp/atlas-draft-XXXXXX.md)
cat > "$CONTENT_FILE" << 'EOF'
[file content]
EOF

# Build the branch name
BRANCH="atlas/[agent]/YYYY-MM-DD-[slug]"
# Example: atlas/meeting-agent/2026-06-15-team-sync

# Invoke the script
/srv/finco/repos/FinCo-OS/_Vault/Atlas/agent/tools/vault-propose.sh \
  "[vault-path]" \
  "$CONTENT_FILE" \
  "$BRANCH" \
  "[PR title in conventional format]" \
  "[PR body with context]"

# Clean up
rm "$CONTENT_FILE"
```

**Branch naming convention:**

| Agent | Prefix |
|---|---|
| Meeting-Agent | `atlas/meeting-agent/` |
| Ops-Agent | `atlas/ops-agent/` |
| Cycle-Agent | `atlas/ciclo-agent/` |
| Compliance-Agent | `atlas/compliance-agent/` |

**PR title convention (Conventional Commits):**

| Change type | Prefix |
|---|---|
| New minutes | `feat(meetings): Minutes [Type] YYYY-MM-DD` |
| DRI Map update | `chore(ops): DRI Map post-meeting YYYY-MM-DD` |
| New decision | `feat(decisions): DEC-NNN [title]` |
| Cadence update | `feat(cadences): [Cycle] evidence YYYY-WNN` |

---

### Step 3: Capture PR_NUMBER and PR_URL

The script prints to stdout:

```
PR_URL=https://github.com/FinCo/FinCo-OS/pull/NNN
PR_NUMBER=NNN
```

Capture both variables for the following steps.

---

### Step 4a: Free zone: immediate auto-merge

For paths in `Meetings/`, `Dev/Backlog/`, `Operations/Cadences/`, `Products/*/Bitacora.md`:

```bash
MERGE_OUTPUT=$(bash /srv/finco/repos/FinCo-OS/_Vault/Atlas/agent/tools/vault-merge.sh \
  "$PR_NUMBER" \
  "[PR_TITLE]")

MERGE_SHA=$(echo "$MERGE_OUTPUT" | grep '^MERGE_SHA=' | cut -d'=' -f2)
```

After the merge, run vault-sync.sh and continue with the agent's flow (distribute, notify, etc.).

If `vault-merge.sh` fails with exit code 3 (conflicts or unmergeable PR), notify Chief of Staff in `#finco-ops` and escalate to Gated flow.

---

### Step 4b: Gated zone: notify and wait

For paths outside Free zones, send to `#finco-ops`:

```
📋 *[Agent]* proposes a change to the vault.

*File:* `[vault-path]`
*Description:* [one sentence about what it is and why]

Review and approve → [PR_URL]

> Merging the PR confirms the change. If something is not right, leave a comment or close the PR.
```

The agent does NOT advance until Chief of Staff merges or closes the PR:

- **Merge** → effective change. Run vault-sync.sh.
- **Closed without merge** → change rejected. Notify and ask whether to review the draft.
- **Comments** → propose a revised version by opening a new PR.

---

### Step 5: Post-merge sync

Always after a merge (auto or manual):

```bash
bash /srv/finco/repos/FinCo-OS/_Vault/Atlas/agent/tools/vault-sync.sh
```

Under normal conditions the cron `/srv/finco/runtime/sync-fincoos.sh` (06:00 UTC) also handles this, but for Free zones the immediate sync ensures consistency before distributing.

---

## Frequent errors

| Error | Cause | Solution |
|---|---|---|
| `422 Reference already exists` | Branch already exists | Change the slug or add a timestamp to the name |
| `404 Not Found` on repos | `GITHUB_REPO` is incorrect | Verify it is `FinCo/FinCo-OS` |
| `401 Unauthorized` | `GITHUB_TOKEN` expired or lacks permissions | Rotate token in `default.env` and restart container |
| `python3: command not found` | `python3` is not in the container | The `nikolaik/python-nodejs` image includes it; verify image |
